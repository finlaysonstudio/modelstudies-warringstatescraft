# CLAUDE.md

> Keep this file and README.md in sync. When changing scope, tools, targets, or conventions, update both documents. CLAUDE.md is the agent-facing source of truth (how to work); README.md is the human-facing source of truth (what this is and how to use it).

## What this is

Warring States Craft: a branching multi-model war game + values instrument + judges' box, targeting the ChinaTalk "Evals for the Situation Room" contest (deadline 2026-09-01). The active plan is `var/plans/20260816_PLAN_SITUATION_ROOM_SUBMISSION.md`.

## Working rules

- Run `npm test` and `npm run typecheck` before declaring a task done; `npm run format` before committing.
- TypeScript, ESM, moduleResolution bundler, no build step for node packages (each exports `./src/index.ts`). The app builds with Vite.
- Throw `@jaypie/errors` classes, never vanilla `Error`.
- All LLM calls go through the injected `LlmClient` seam (`@modelstudies/workflows`); all persistence through the `Store` seam (`FileStore` rooted at git-ignored `var/`, one directory per model). Never import `@jaypie/llm` from browser code.
- Legacy OpenAI subjects (`packages/workflows/src/llm/legacyOpenAiClient.ts`): `gpt-4-0613`, `gpt-4`, and `gpt-3.5-turbo*` predate structured output (the Responses API rejects `json_schema` for them and ignores tools on `gpt-4-0613`), so `createLlmClient` routes an id in `LEGACY_OPENAI_MODELS` to a Chat Completions client that satisfies `format` with a forced function call, sends no temperature (the API default the paper's `create_chat` used), retries 429/5xx with backoff, and stamps usage with the snapshot the response names. The paper's `gpt-4-1106-preview` and `gpt-3.5-turbo-16k` are retired; `gpt-4-0613` (8k window; a dialog-3, 350-word game peaks near 6.9k tokens on the move-two decision call) is the surviving GPT-4 of that generation, and `gpt-3.5-turbo-16k` now aliases to `gpt-3.5-turbo-0125`. That path is not strict mode (`required` is advisory and a missing key is not an API error), so `gpt-3.5-turbo-0125` flattens a two-array schema often enough to be unfieldable; the capability table (`packages/workflows/src/llm/capabilities.ts`: `ElicitationMode` = `schema` | `text`, `TEXT_ELICITATION_MODELS`, `elicitationFor`) routes it to the text path and `gpt-4-0613` stays on the schema (80 clean arms of `study_a82834f2`).
- Text elicitation (`GameOptions.elicit`: `auto` (default, the capability table) | `schema` | `text`; `--elicit <mode>` on `game-run` and `study-run`; `Run.elicit: "text"` recorded when any seat used it, `Study.elicit` carried onto every arm, `LamparthGroup.elicit` on the report row): on a forced-choice turn a `text` model is asked twice in plain text with no `format` (`answersPrompt` withholds the menu and asks the turn's questions; `selectionPrompt` puts the menu and one instruction with the answers on the history), and `parseSelection` matches the reply against the menu. Only the selection call repeats on an invalid selection, so a retry never re-pays for the prose; `validateChoices`, `CHOICE_RETRIES`, `retries`, and `unusable` are unchanged, so the failure vocabulary and the report's exclusion are the ones already on record. The parser is deliberately narrow because single-letter ids collide with English articles (`a` is both "Military Action" and the indefinite article): the last line (or every line of a bracketed list) is read as ids only when it is id-shaped, otherwise only bracketed ids count, and with no id at all the phrases are matched against labels (exact, then a unique prefix; an ambiguous prefix is dropped, not guessed). The memo path is refused: a `text` model on a non-`choice` scenario throws `ConfigurationError` at engine construction, because `memoFormat`'s two arrays have the same exposure and nothing validates them. Two elicitations of one report is a confound, so a paired text-elicited cell of a schema model measures it.
- Dependency direction: `game`/`survey`/`judges` → `workflows`; `lake` depends on nothing but `@jaypie/errors`; `cli`/`app` → all. `app` imports types only from node packages.
- Scenario content is data (`packages/game/src/scenario/`); engine code stays scenario-agnostic. The thirteen period scenarios are chapters of one chronicle (the Seven Courts saga, `var/plans/20260823_Plan_seven_courts_saga.md`): a `ScenarioText` (`scenario/render.ts`) written once per language (`en`, `zh`) against gazetteer keys (`{qin}`, `{river}`, `{Clan}` capitalizes in en) and rendered by `buildChapter(text, { naming, language, pivot })` into a plain `Scenario`. The world module (`packages/game/src/world/`) holds the gazetteer (`GAZETTEER`: every state, body, place, river, pass, with `chronicle` (real names, the default), `masked` (the invented toponyms), and `modern` (the strait and the sea) renderings in both languages; it is `CAST_NAMES` + `PLACE_NAMES` + `FEATURE_NAMES`, the last being the named country the map draws but no seat marches to — the Wei, the Fen, the Han, the Min, the Eastern Sea, the Yunmeng marshes, the pass road, the plank roads. A feature is a gazetteer key and not a `PLACE_NAMES` key on purpose: `mentionsOf` sweeps `PLACE_NAMES` to aim a stage direction, so every key it can return has to be a place the map carries, while every key in `GAZETTEER` tightens the masked-leak check the chapter specs run), the cast (`CAST`: a durable `character` block per state, undated; it is prepended to a seat's brief when `ScenarioSeat.state` names a member), the chronicle (`CHRONICLE`: per-chapter `remembers` lines per state; `memoryBefore(state, order)` builds the "What your court remembers" block from every earlier chapter), and the vocabulary sheet. Registration order in `scenarios.ts` (`TEXTS`) is chronicle order, strict chronology: 0 `strait-states` (prologue, c. 485, Wu/Yue/Qi, structure frozen as the Lamparth bridge; `taiwan-strait` is its modern-noun twin outside the chronicle), 1 `land-register`, 2 `salt-and-iron`, 3 `heavy-coin`, 4 `famine-granary`, 5 `schools-of-the-hundred`, 6 `royal-domain`, 7 `conscription-rolls`, 8 `borrowed-road`, 9 `corridor-states`, 10 `hostage-prince`, 11 `river-works`, 12 `assassins-map`; then `PLAIN`: `taiwan-strait` and the eight `lamparth-2024-*` cells (one rendering, refuse any option). `getScenario(id, options)` renders and caches; `renderingsOf(id)` is namings × languages. Seat ids are cast keys (`qin`, `zhao`, `qi`, `council`, `mohists`); seat names and chapter titles are rendered from the gazetteer. No real person is named in played text, no year is stated (`Scenario.chapter` carries `order` and `date` for readers), and the anachronism table in the plan §1.3 is enforced by `RETIRED_TERMS` in `__tests__/chapter.ts`. Every chapter's spec calls `expectChapter(text, shape)` (en/zh isomorphism, every placeholder resolved, no modern noun, no retired term, no chronicle name under `masked`, every pivot applies) and every chapter carries `STANDING_PRIORITIES` (`scenario/shared.ts`) verbatim. `Pivot`s (`{ id, note, en: {from, to}, zh: {from, to} }`) name one pivotal phrase that occurs exactly once and substitute it before rendering; `--pivot <id>` stamps `Run.pivot` and is the treatment for "a pivotal phrase read two ways". Engine strings (`strings.ts`, `EngineStrings`, `stringsFor(scenario)`) are a table keyed by language: the `en` table is the original wording byte for byte (the Lamparth specs depend on it), and a `zh` run is judged and narrated in zh by the same table. Translation fidelity is a documented limitation: the two bodies are written, not translated, and `expectChapter` checks shape, not meaning. `Scenario.simulates` (required, `Headline: detail`) names the modern situation for readers, is rendered on the chapter pages and `/craft/play`, and never reaches a model prompt (`materials.spec.ts` checks it for every rendering, and sweeps every period rendering for `MODERN_NOUNS`; `taiwan-strait` and the Lamparth cells are exempt by id). CLI: `--language en|zh`, `--naming chronicle|masked|modern`, `--pivot <id>` on `game-run` and `study-run`; the run and the study record them.
- Lamparth replication (`packages/game/src/scenario/lamparth2024.ts`): the Lamparth et al. 2024 U.S.-China game transcribed verbatim from the MIT repo's `wargame/*.txt` (Appendix A); `buildLamparth(treatment)` builds one of eight cells (`accuracy` × `training` × `posture`; ids `lamparth-2024-<acc70|acc95>-<basic|significant>-<revisionist|statusquo>`, `LAMPARTH_2024` is the repo default acc95/basic/revisionist). It uses three scenario-agnostic engine features: `Scenario.elicitation: "choice"` (seats answer `turn.questions` and select ids from `turn.choices`; `choiceFormat(turn)` constrains the schema enum; the memo carries `answers` and `choices`, `decision` = selected labels, `options` = the menu), `ScenarioSeat.scripted` (the seat plays `turn.script[seat]`, roster records `SCRIPTED_MODEL`, no LLM call, no debrief; the matrix fills it itself and refuses a model on it), and `Scenario.record: "scripted"` (the public record between turns is the injects and scripted moves, no narrator text). Run-level treatments: `GameOptions.dialog` (N rounds of simulated team dialog before each model decision, carried as chat `history` into the decision call; the brief keeps `dialog[]`), `GameOptions.dialogWords` (a target stated in every dialog prompt, `(about N words for this round of dialogue)`; the paper's chunks were about 350 and its measures move with length, so a length-matched run passes 350; the original enforced nothing and the seam has no portable output cap, so this is an instruction, and the report carries the achieved mean per move as `dialogWords`), and `GameOptions.priorities: false` (withholds the priorities block); the run records `dialog`, `dialogWords`, and `priorities`. CLI: `--dialog <n>`, `--dialog-words <n>`, `--no-priorities`. The cells declare `seatPrompt: "bare"`: the seat's system prompt is the brief and the priorities block only, because the engine's `framed` prompt carries `summary` (which for these cells names the paper, the treatment, and move two's outcome), objectives, the ladder, and a closing line; `lamparth2024.spec.ts` asserts none of that reaches the seat. Forced-choice selections are validated (`validateChoices` in `briefs.ts`: empty, duplicated, or whole-menu selections are invalid); `elicitBrief` retries the decision call up to `CHOICE_RETRIES` times with the invalid reply on the history and `choiceRetryPrompt`, records `retries`, and when the last attempt is still invalid records `unusable` (the memo keeps what the model returned). `selectionFor` and the Lamparth report skip unusable briefs; the report counts the dropped games as `excluded` per group rather than coding them as zeros. The cells declare `report: "lamparth"`; `choices.ts` keeps per-turn helpers (`choiceStats`) for ad hoc grouping.
- Studies and reports: a study (`packages/game/src/study.ts`, `Study` in `types.ts`, files in git-ignored `var/studies/`) is scenarios × models × replicates, each arm one root run stamped with `run.study` and `run.replicate`; `planStudy` writes the arms, `extendStudy` grows a study in place (raises `replicates` and/or adds `models`, appending only the missing (scenario, model, replicate) arms as pending after the existing ones; played arms and their runs are untouched; refuses a lower count or a no-op; a default title follows the new shape), `runStudy` plays every arm that is not complete (an arm whose run finished with a failed model brief is an error and is replayed as a fresh run; an active run is resumed), `buildStudyReport` runs the study's reporting definition. Reporting definitions live in `packages/game/src/reports/` (`REPORTS`: `basic` = escalation per turn/peak/final across replicates; `lamparth` = the paper's statistics: action frequency, total causal effect per treatment factor, aggressiveness, actions selected, Table 2 consistency, and subject-minus-reference differences, every interval a seeded percentile bootstrap); `Scenario.report` names a scenario's definition (default `basic`), a study inherits it and refuses mixed scenarios without an explicit `--report`. Adding a definition: implement `ReportDefinition`, register in `reports/index.ts`, extend `ReportId`, mirror the report shape in the app types. The Lamparth report imports `packages/game/src/reference/lamparth-2024.json` (`LAMPARTH_REFERENCE`, a package asset rather than a store model; the MIT repo's human, GPT-4, and GPT-3.5 dialog-3 games as choice flags only; the repo's GPT files reproduce the paper's Table 2 as the joint probabilities p(agg2 ∧ agg1) / p(agg2 ∧ des1), which the report carries as `table2` beside the literal `conditional`). CLI: `study-run --scenarios "lamparth-2024-*" --models SOL,LUNA --replicates 10 --dialog 3` (`--plan-only`, `--resume <id>`, `--concurrency`; `--resume <id> --replicates 10` and `--resume <id> --models X,Y` extend the study before playing), `study-list`, `study-report <id>` (writes `var/reports/<id>.json`). App: `/craft/studies/:id` and `/awry/studies/:id` (the report rendered, then the arm grid with replay links; the page computes nothing).
- Re-adjudication (plan `var/plans/20260825_Plan_study_adjudicate.md`): a study whose seats, judge, and narrator are all the same model cannot separate a difference in play from a difference in scoring, so `adjudicateRun` (`packages/game/src/adjudicateRun.ts`) re-scores a stored run with a fixed panel and writes an `Adjudication` beside it (store model `adjudications`, `var/adjudications/<runId>.<panelId>.json`, `TurnScore` per turn). The run is never touched: the games on disk are the evidence and only the scoring is in question, so the artifact carries scores and never narrative. Three rules. (1) The judge reads the record as played, truncated: `publicRecord` folds every adjudicated turn of the run it is handed into prior-turn headers, and the engine scores a turn _before_ pushing it, so turn _i_ is scored against `{ ...run, turns: run.turns.slice(0, i) }` and those headers keep the **original** rungs and narratives — the seats played against that record, and rewriting it would score a game no seat ever saw. That also makes every (run, turn) pair independent, which is what lets the pool be over pairs (`Gate`, `createGate`, shared across runs by `adjudicateStudy`). (2) Inherited turns are scored once: a decision-point child copies its parent's `TurnScore` for every turn before the fork (`planAdjudication`, `parentOfAdjudication`/`parentOfRun`, `inherited: true`), which on `study_48eec99d` is 768 of 2,256 scored turns. (3) Cost follows the artifact: the new judges' spend lives on the `Adjudication` (`usageOfAdjudications` in `cost.ts`), `usageOf(run)` keeps reporting what the run cost, and `applyAdjudications` strips usage from the verdicts it overlays. `scoreTurn` (`adjudicate.ts`) is the one implementation of the judge prompt, the clamp, the median fold, and the `unscored` rule; `adjudicateTurn` is `scoreTurn` plus the narrator. `panelIdOf` is `p` + sha1 of the sorted judges and the mode, so the id does not move with the order they were typed; `--as <name>` overrides it. Reports: `applyAdjudications(runs, sets)` swaps each turn's panel, mode, escalation, and unscored flag and keeps the narrative and `narratorUsage`; `buildStudyReport --adjudication <name>` overlays, stamps `ReportBase.adjudication` and `adjudicated` (`{ runs, of, usage }`, the re-scoring's own spend beside the unchanged play cost), and writes `var/reports/<studyId>.<panelId>.json` so a re-scored report never overwrites the study's own. A partial overlay is refused unless `--partial`, never dropped silently. CLI: `game-adjudicate <runId>` and `study-adjudicate <studyId>`, each `--judges A,B,C` (through `resolveModels`, so `LUNA` or a literal id) `[--judge-mode median] [--as <name>] [--force] [--concurrency <n>] [--dry-run]`; `--dry-run` prints the call count and prices it from the judge calls already on record, per judge, each figure naming its source.
- Fork modes: `GameOptions.matrix` (seat → candidate models) forks at turn 1 into one child per combination (`branch.lane: "matrix"`, root keeps `run.matrix`, no turns) and children never fork again; without a matrix the root plays to the scenario's decision point and forks n·2 (independent + consensus). `matrixCombinations` is the single source of the product.
- Human play: `GameOptions.human` (a `HumanPlayer`: `decide`, optional `judge` and `narrate`); any seat assigned `HUMAN_MODEL` (in `seats` or in the matrix) routes to the human every turn; `HUMAN_MODEL` on the panel routes a `JudgePrompt` to `judge` and as the `narrator` routes a `NarratePrompt` to `narrate` (the engine refuses either without the handler). Masking helpers live in `mask.ts`. Within a turn, model seats decide first and human seats last; the `HumanPrompt` carries `roster`, `history` (that run's own prior turns) and `table` (the other seats' briefs this turn). Decision-point fork with `human` set adds a blind and an informed focal memo beside the roster. Human prompts are masked: every model id other than `HUMAN_MODEL` reads `MASKED_MODEL` (roster, history briefs, panel) and the `table` is shuffled; the stored run keeps the truth. The play console withholds replay links from a seated human until the session completes. The browser path is `packages/app/server/play.ts` (Node-side, loaded by the Vite plugin through `ssrLoadModule`, sessions in memory, matrix only) behind `/api/play/*`, and the console page (`pages/PlayConsole.tsx`), unrouted in this build: live play is a later registration-gated deliverable. The server module is the one place in `app` that imports node packages at runtime; browser code still imports types only.

Routes: `/` home, `/craft` (chronicle, studies, survey card, play card), `/craft/chapters/:id`, `/craft/studies/:id`, `/craft/survey`, `/craft/replays/:id` (+ `/matrix`), `/craft/play` (+ `/:id`), `/world` (`pages/world/WorldHome.tsx`: a card apiece for the map, the city, the village, the house, and the tiles), `/world/map` (the overworld explorer), `/world/city`, `/world/village`, `/world/house` (one route per `SITES` entry), `/world/tiles` (the art showcase), `/awry`, `/awry/studies/:id`, `/awry/replays/:id`; unknown routes render home with a not-found line, the old `/craft/map`, `/craft/<site>`, and `/craft/tiles` addresses redirect to `/world/…` keeping the query string (`MovedToWorld` in `main.tsx`), and a run or study under the wrong campaign redirects to its own (`useCampaign` reads the route, `campaignOf` the data). The replay library (`packages/app/src/lib/library.ts`: `libraryOf`, `matchGames`, `pickRandom`; membership = complete, turns > 0, no human seat) feeds play and the chapter pages. Replay renderers live in `packages/app/src/components/replay/`; the awry summary (`pages/awry/Summary.tsx`) reads every number from the study's lamparth report and types none. `/craft/play` narrows the library by chapter, followed seat, and opposing models (query-string addressable; `pickRandom` is seeded so a reload keeps the pick); `/craft/play/:id` reveals the recorded game step by step from the followed seat's vantage (inject, the seat's brief, the table collapsed, the panel's verdict, the narrative; space advances). `/craft/survey` renders the values scorecards, every ladder scorecard (`?plan=` switches), the fieldings on record, and the instrument description; `/craft/survey/:interviewId` is one sitting with per-repetition codes and probed explanations. `cli materials` also exports `var/instruments/<plan>.json`, and the dev server adds `/data/fieldings.json` and `/data/probes/<interviewId>.json` (the sitting's probe files gathered into one array).
- Stage (plan `var/plans/20260823_Plan_stage_animated_overworld.md`, status §10): every replay on `/craft/play/:id` plays on a Phaser 4 overworld above the turn cards. The script is data: `StageScript` (`packages/game/src/stage/types.ts`, store model `stagings`, `var/stagings/<runId>[.random<seed>].json`) is beats keyed by id (`t<n>.inject`, `t<n>.brief.<seat>`, `t<n>.verdict`, `t<n>.narrative`, `debrief`), each a list of directions from the closed vocabulary (`vocabulary.ts`: `StageDirectionKind`, `DIRECTIONS` (places `at` | `route`, archetype, effect), `StageArchetype`, `StageEffect`, `Marker`, `Terrain`, `Water`), `seats` (state, home place, model), and `places` used; `validateStageScript` refuses an unknown place, a route kind without `from`/`to`, or an `at` on a route kind. Three coders: `fallback` (`fallback.ts`, escalation band → `CONSEQUENCES` kind, no model call; `weave.ts` steps a route consequence down a band when the escalator is already at the focus), `random` (`random.ts`, seeded, every seat picks a strategy at random so the weave is exercised; stored beside the default as `<runId>.random<seed>`), and `coder` (`coder.ts`, Sonnet by default, one call per turn through the seam with `format`, invalid replies retried with the validator's message; about $0.17 per six-turn game). CLI: `game-stage <runId> [--fallback | --random --seed <n> | --model <id>] [--force]`, `study-stage <studyId> [--fallback] [--model] [--force] [--concurrency]` (every complete arm), `stage-map --check` (every gazetteer key and home has a place on the map). Homes: `homes.ts` (`han` = `yiyang`, `zhou` = `luoyang`). Art sets (`packages/app/src/stage/sets.ts`, browser-safe and imported by the node build scripts): a set is a tile size, the art layers it stacks, and its own Tiled map, and `STAGE_SETS` holds two — `period-16` (fallback, vendor, period at 16 px, `overworld.tmj`; the period layer draws its own sixteen terrains and derives everything else from `period32`, so both sets carry the whole catalog) and `period-32` (those three plus `period32` at 32 px, `overworld32.tmj`, the same country one shading grade higher). `DEFAULT_STAGE_SET` is `period-32` and is the only place the default lives; `BASE_TILE` (16) is the size every scene constant is written at. No page offers a choice of set: every page mounts `stageSet(DEFAULT_STAGE_SET)`, there is no `?set=` and no picker, and `period-16` survives as a build target and as `stage:preview --set` (`stageSetOf` resolves an unknown value to the default rather than failing). Map: `packages/app/art/map/geography.json` (fills, places, and `decor` placements on a 144 × 96 grid drawn against the historical geography, c. 250 BCE) is rendered by `npm run stage:map` to one `.tmj` per set (Tiled JSON, blob autotile indexes per ground, water tilesets with stacked frames, a `decor` object layer of embellishments (`DECOR` in `catalog.ts`: pine, bamboo, beacon, tumulus, stele, boat, horses, grove, rocks), and a `places` object layer with `type` = marker and `state`); `placesOfTiledMap` / `checkPlaces` in `tiled.ts` read only the `places` layer. A fill may also carry a `feature` (a gazetteer key), which is how the map knows the river it draws at 96,20 is the He and the one below it is the Wei. The `luliang` fill is the same device on dry ground: the range on the east bank of the gorge is a terrain _and_ a named feature, so a click reads its own name under either naming rather than the terrain note's fixed title. It is on the east bank because that is where the range is — the Jin-Shaan gorge runs along the eastern Ordos block and the western piedmont of the Lüliang, so the Shaanxi bank is dissected loess with no range on it at all (the ground the map already labels `xihe`) and the Shanxi bank rises straight out of the water. The strip of generic `mountain` that used to sit on the west bank is gone, which leaves `terrain.mountain@loess` and `water.river@mountain` built but unlaid. The build names everything it carries and does not lay (`unlaid:`), because an unlaid sheet is invisible and neither kind is a fault: a sheet is the record of a generation, and the vocabulary is allowed to run ahead of the geography. The two are measured differently — a plain terrain against the grid, since `buildTiledMap` registers every ground whether or not a fill uses it, and a pair against the map's own tilesets, since a pair is registered only where it is actually laid. Today that is `terrain.cobble` in both sets and those two pairs in `period-32`. The three `changcheng` fills are the long walls (Zhao's and Yan's northern lines inside the steppe band, Qi's along the downland between the plain and the sea); they run in `terrain.wall` rather than the `cobble` they were first laid in, and each is an orthogonal polyline on purpose, because a corner-Wang blob sheet connects through shared corners and a diagonal step reads as two bars touching at a point rather than as one wall. Ground and feature are rasterized in one pass (`rasterMapOf` → `RasterMap`; `rasterize` is the grid alone), so a later fill takes the cells it overpaints and a stretch is named only where it still shows, and `featureFileOf` writes the result to `public/stage/features.json` (`FeatureFile`: feature id → cell indexes) once for every set, because the grid is the same at every tile size. The sidecar is what keeps the browser scene off the node build module. The build reports each set's ground coverage (`coverageOf`: `missing`, `mismatched`, `short`), because a sheet drawn at another set's tile bound into this set's tileset renders as garbage rather than as nothing. Art layers (`packages/app/src/stage/assets.ts`, `loadStageManifest({ set })`, `STAGE_SOURCES` in order; a set names the layers it stacks and the manifest carries `set` and `tile`, and every asset its own `tile`, so the scene scales a lower layer's art by `scaleOf` = `unit * BASE_TILE / asset.tile`): `fallback` (procedural, `npm run stage:fallback`, `art/fallback/`, committed), `vendor` (the purchased packs, `npm run stage:vendor` over `art/vendor/packs.json` and `var/assets/vendor/`; an a2 / a1 sheet's `layout` (`A2Layout` in `autotile.ts`, declared per pack or per sheet) names its block's top row: `single-corners`, the VectoRaith sheets, is the single tile then the inner-corner tile, with the fill only inside the box, and `corners-fill`, the RPG Maker convention and the default, is the inner corners then the plain fill; `expandA2Block` copies the one whole tile the layout provides (the single or the fill) and composes the rest, and `fillTileOf` (the key-out base) follows it; the output `public/stage/vendor/` is git-ignored, and nothing from the packs is committed or uploaded to any generator; the packs' license forbids AI use), `period` and `period32` (generated on PixelLab for this project; a `PeriodSpec` carries its own identity — the `source` it writes, the `tile` its ground sheets are drawn at, the raw `root`, and the built `out` — so a second resolution is a second spec file rather than a second script: `art/period/items.json` is the 16 px spec and prompt record (`npm run stage:period` → `public/stage/period/`) and `art/period/items32.json` the 32 px one (`npm run stage:period32` → `public/stage/period32/`), raw downloads in git-ignored `var/assets/pixellab/`, both layers committed; a spec may name a sibling spec in `derive` (`items.json` names `items32.json`), and `buildPeriod` then fills every id the spec does not draw itself by box-downsampling that spec's _built_ layer to its own tile (`downsampleImage` in `vendor/png.ts`, alpha-weighted so a one-pixel outline lands as a darker edge rather than a dotted line; `scaleEntry` halves every dimension the entry carries — frame, sprite frame, kit cell — and refuses one the factor does not divide), so the settlement art generated once at 32 px (171 ids: the kits, the furniture, the townsfolk, the yards, and the pairs) draws in both sets and a generation is spent once; the derived record keeps the source's prompt and job and carries `derived: "period32"`, `showcaseOf` counts its generations toward neither layer's total (`derived` on the showcase), and the card reads `from period32`. The bespoke biomes are the terrain vocabulary (`TERRAINS` in `catalog.ts`: grass, tallgrass, scrub, loess, steppe, road, cobble, wall, forest, bamboo, hills, mountain, qinling, taihang, luliang, shu, marsh, field; `RANGES` is the mountain family, `mountain` being the generic style every lesser range wears while the four named ranges carry their own generation), and `MARKER_VARIANTS` maps a marker to alternate assets (town has three) picked per place by a hash of its key. No chapter names one and no episode is set at one, which is the point: they are drawn for a reader of the explorer, not for a scene. An `image` item takes the same `desaturate` / `adjust` finish a sheet does (`applyFinish` in the build's image branch), because the generator drifts rock toward violet whatever it is drawing and a marker off the map's range is the same fault as a tile off it; a `sprite` item takes it too, over every frame of the walk and the poses, because a standard-mode quadruped (`sprite.ox`, the one figure v3 cannot draw) comes back in whatever colour the generator likes and a recolour costs no generation where a re-roll costs its walk again. Four `items.json` options finish a generated sheet, because the generator picks its own palette and paints its transition against the one lower terrain it was chained to: `key` drops what must not travel with the biome (`lower` keys the lower palette out so the map's own layer shows through the surround instead of a collar of grass; `upper` keeps only the upper terrain's colours, which also drops the warm collar the generator paints across a transition — right for a biome whose pure tile is rich enough to carry its own outline, wrong for one of two or three colours, which upper-keying strips to a flat cut), `adjust` (`ColourAdjustment`: `hue` in degrees, `saturation`, `value`) brings a sheet into the map's range without spending another generation, `variants` stacks rearrangements of a `fill` sheet with `variantTone` giving each block its own tone, and `frames` stacks the water animation. `blocksOf` in `map/map.ts` is the one rule for how many blob blocks a ground's plain sheet carries (a frame apiece for water, a rearrangement apiece for every ground on land) and every art layer builds to it, because the layers shadow one another by id and a layer with fewer blocks than the map addresses renders blank. Land takes rearrangements and water takes frames because they are the same stack: a cell picking its own frame out of a wave would shimmer against its neighbours, so water spends the stack on motion and land on variety. The rule has no exceptions on land, including the grounds the geography lays as a one-tile ribbon with no interior at all (the roads and the walls today), because which grounds have a wide field is a fact about the country and the art build must not shift when a fill moves. `pairBlocksOf` is the pair's rule: a pair draws one boundary and a boundary is never rearranged, so a land pair carries one block where its plain sheet carries four, and water still needs its frames. Only the period layers declared their own count, and they no longer do — `buildPeriod` derives it from `blocksOf` (`groundOfId` names the plain sheet's ground; a pair or a non-ground gets one block) and `items.json` keeps only `variantTone`, because a sheet short of what the map addresses renders blank and the author is the one who would forget. `variantSheet` rearranges only the tiles it is given (`vary`, the fully surrounded tile by default) and copies every other tile of a later block verbatim from the first: the map addresses a later block only where a cell is fully surrounded by its own ground, since an edge tile's art faces its boundary and a cyclic shift would wrap that boundary around the tile, so copying the rest keeps the sheet honest about where a block differs. A block is not a frame: `blobTileset` takes `blocks` (how tall the sheet is) and `frames` (how many of those blocks are a Tiled animation) separately, and only water passes more than one frame, because Phaser plays a declared animation and a grass sheet declared as frames makes every cell that lands on the first block cycle through the rest while its neighbours sit still. The map builder gives each fully surrounded tile one of two orientations (`orientationOf`, Tiled's flip flags added, never OR-ed) and one of its plain sheet's stacked rearrangements (`variantOf`; a cell laid from a pair sheet takes neither, since that sheet is a boundary): the horizontal mirror is the only one, because top-down art is lit from the top of the tile and mirroring it across the horizontal axis moves the light to the bottom, which turns a field of any shaded ground into a checkerboard of alternating light (a hill drawn as a lit crown over a shadowed lower side is where it shows worst). A generated Wang fill is flat by construction, so a wide field's variety comes from rearranging its few pixels rather than from a busier tile. The loess is what widened the rule past grass: a ground drawn as landform rather than as texture carries a directional motif, and the mirror then pairs adjacent tiles into a symmetric ornament, which reads as wallpaper where a flat ground reads as noise. The cost is real and worth stating — every land sheet is four blocks tall in all four layers, which is about 4 MB across `period32`, `period`, and `fallback`. Transitions (`pairIdOf`, `againstOf`, `groundMask` in `map/map.ts`): keying answers a ground that meets grass, but where two non-grass grounds meet neither was drawn against the other and the layer beneath is not grass, so the set carries a sheet per adjacency, `terrain.mountain@forest` being the range drawn over the wood. Each is generated chained at both ends (`lower_base_tile_id` and `upper_base_tile_id`), which is what lets it be laid in place of the plain sheet with no seam: `var/scratch/verify-pairs.mts` checks that every pair reproduces both neighbours' base tiles pixel-exactly. A pair is generated at `transition_size` 0.25 (0 where two flat grounds meet, since a Wang transition tile is itself an edge and neither ground has the relief to spend on one), never 0.5: `wangBlobSheet` samples the quadrant of the Wang cell centred on each tile corner, so a band deep enough to run past that corner leaves no pure lower ground anywhere in the composed sheet, and the pair tile — opaque, since a chained sheet is never keyed — then covers its neighbour square to the tile edge, which is a hard axis-aligned cut where a drawn boundary should be. `var/scratch/lower-share.mts` reports the share of each built pair that is its lower neighbour's own colours: 17–33% at 0.25 or 0, and 0–11% at 0.5. How many tiles come back is what `transition_size` really decides, and pro mode moves the threshold: standard returns the 16-tile Wang sheet at 0, 0.25, and 0.5 and the 25-tile `tileset15_t1` cliff sheet at 1.0, while pro returns the cliff sheet from 0.5 up. A cliff sheet's pure-lower corner is a transition tile rather than the ground it was chained to, so a range generated pro at 0.5 cannot reproduce the field it stands in and has to be keyed out, which cuts its drawn scree into floating specks; every pro range is generated at 0.25 for that reason, and it is the tile count in the reply, not the setting, that says which sheet arrived. Pro's shape controls (`raggedness`, `slope_size`, `spread_x`) are the other reason to reach for it, and the loess is the case that shows what they answer: six generations of prompt and shading gave six flat fills, because a texture is what wording moves and a dendritic gully network is geometry. Four candidates were run side by side and compared as autotiled patches over grass (`var/scratch/loess-cand.mts`, which is the way to judge a ground — a lone sheet says nothing about how it tiles), and only the pro one at `raggedness` 0.55 drew the branching tree. The rule that follows is which knob to reach for: shading and wording move the texture, and only the shape controls move the landform. Chaining fixes the base tile and nothing else: a sheet can reproduce the tile it was given and still draw the rest of its range in its own palette, so the build recolours rather than corrects. `matchPalette` (`tileset.ts`) maps an image from one palette onto another by luminance rank weighted by area (rank, because two renderings of the same material carry the same few shades in the same order and rank keeps the shading a nearest match would flatten; weighted, because they do not carry the same _number_ of shades, and spreading nine evenly over six puts the body of one on the highlight of the other — so a `Swatch` is a colour and the pixels of the plain tile wearing it, `cornerSwatches` counts them, and each shade lands where the same share of the target's area lies). The plain tile decides the mapping but is not what the sheet wears: a generator draws the boundary in shades the plain tile never carries, and every one of those otherwise snaps to whichever entry it sits nearest, so a wide lit shoulder a shade off the ground's highlight becomes the highlight outright and the map reads a pale ribbon tracing every boundary. `matchPalette` therefore also takes `area`, the histogram of the region being recoloured (`splitFinish` classifies each pixel before recolouring so it can count both halves), and places a colour `from` does not carry by its own share of that region instead. How much of the region it covers decides which placement to trust (`BODY_SHARE`, 5%): a shade covering a body's worth of the region is that ground as this sheet draws it and goes where its own area puts it, which is the case `upperTarget` exists to close (a pair whose turf is a shade off the plain sheet's beside it — `terrain.hills@forest` drew 42% of its half in a colour the plain tile does not carry, and forcing it darker left the pair a visibly different green); a rarer shade is a detail — a rim, a fleck, a dithered edge — where the area of a handful of pixels says nothing, so it follows its nearest neighbour and may only ever be darkened, because the fault that rule was written for is a band reading brighter than the ground it belongs to and a correction that could also lighten would put a new light mark on the shore. The entries `from` does carry keep their `from`-derived place, so the base tile still reproduces pixel for pixel. `var/scratch/rim-share.mts` is the check: the share of a pair drawn in its ground's lightest shade beside the share the plain sheet of that ground wears, and a pair far above its plain sheet has a lit rim (`terrain.hills@forest` was 40 points above and is 7). `paletteAgainst` (`build.ts`) reads the colours a ground actually wears on the map from its own sheet _as the build finishes it_ (`finishedSheet`, cached and recursive: a plain sheet is itself drawn against grass, so reading its raw tile answers with colours the map never shows, since `splitFinish` repaints every pixel it classifies as the lower ground — that gap is what left the hills pairs a grade lighter than the hills), and `splitFinish` takes both halves' targets: `lowerTarget` puts a chained sheet's surround onto the ground it stands in (the lime rim the bamboo grove wore is what that removed), `upperTarget` puts a pair's own half onto the plain sheet of the same ground (the ice-blue patch the Taihang wore wherever `terrain.taihang@scrub` was laid is what that removed). Both are identity for a sheet that already matched, and `var/scratch/pair-palette.mts` reports any colour in a built pair that belongs to neither neighbour. Which half a pixel belongs to is nearest palette, then two rules where nearest cannot answer. A colour both plain tiles carry is nearest to both, and a tie broken by which half is tested first hands a terrain's own body to the other one: the downland's turf is 40% of its plain tile and a handful of pixels of the meadow's brightest highlight, so an equal distance sent every one of those pixels to the meadow and the whole hills region came back painted in grass's lightest shade — a flat pale shelf a tile deep wherever the region's edge ran straight, which is the white bar the map read at every hills boundary. A tie therefore goes to whichever ground wears the colour by area (`sharesOf`); only on a tie, since a strictly nearer palette is still the answer. And the two plain tiles' boxes (`lowerBox`, `upperBox`, from `wangIndex`) are each one terrain by construction, so no guess may hand their pixels to the other half: left to the guess, a fraction of a percent of a plain upper tile comes back wearing the lower ground, and that tile is what `paletteAgainst` hands every pair of the ground as its target, so a rare stray becomes a slot in the target for a whole transition band to land in — a quarter of `terrain.hills@forest` was grass's light shade, which is a cream bar along every contact. The same tie was the lime speckle the scrub left on the Qinling crags and the Taihang ridge. The entity is a checkpoint written after every item; on resume `loadSitting` folds the journal over it and the journal wins (`materializeResponses`, drift logged). `RunSittingOptions.signal` stops a sitting between calls (an in-flight call lands and is journaled), checkpoints it as `pending` with `statusDetail: "interrupted at <item> rep <n>"`, and writes `stop: interrupt`; the CLI's first SIGINT/SIGTERM aborts, the second exits. `FileStore.update` writes a temp file and renames it. `verifyInterview` (`interview-verify <id> [--rebuild] [--json]`) recomputes every turn's prompt sha1, compares the entity and probes with the fold, and with `--rebuild` rewrites both from the journal (an entity missing from the store is rebuilt from the `start` line). A fielding (`packages/survey/src/fielding.ts`, `var/fielding/<id>.json`) is one `interview-run`: plan, roster, repetitions, and model → interview id, written before the first sitting and settled after; `--resume <fieldingId>` resumes every sitting it opened (a complete one returns as is). tokens per call from a prior sitting of that model on any plan when one exists (`measureUsage`, mean input and output per answer and per probe call), else the stated heuristic (prompt characters / 4 in, 24 out for an answer, 220 out for a probe); dollars from `MODEL_PRICES` at estimate time; every figure names its source (`measured` | `heuristic`). `--budget-usd <n>` on `interview-run` is a `SittingBudget` shared by the roster (`createBudget`, `chargeBudget`, `budgetExhausted`, `budgetDetail` in `interview.ts`): every sitting checks the running sum after each call (an answer and its probe are a pair) and stops as `pending` with `statusDetail: "budget exhausted at $x.xx of $y.yy"` and `stop: budget`; a resume charges what the journal (or, without one, the checkpoint) already holds before asking anything; a fielding-id resume inherits the fielding's recorded cap when `--budget-usd` is absent; unpriced calls count at zero and are named in the detail. `--items <spec>` fields a subset (item names, or one name of a subset the plan declares in `Instrument.subsets`; `interview-cost <id>` (`--json`) folds one sitting by role.

- Arms: a treatment arm is data the plan declares (`Instrument.arms: Record<id, ArmDefinition>` in `types.ts`: `title`, `items` (default the whole bank), `preamble` (replaces the instruction), `probe` (replaces the plan's), `append: "majority"` with `appendText` (`{course}` is the course named), `language` (stamped on the sitting), `rendering` (per item `{ wording, options: [s1, s2] }`, codes unchanged)). `crisis-situated` declares five on the crux: `priorities` (the standing block prepended to the preamble), `informed` (one line appended after the courses naming the course a majority chose; the majority is scheduled 6/6 by `balancedOrders` over the two codes, seed `${plan}:${arm}:${item}` (`:from<n>` on a top-up), independent of option order, recorded per turn as `InterviewItemResponse.majority` and `TurnEvent.majority`; the line names the course by its label because the courses are shown unnumbered), `dress-period` (chronicle gazetteer nouns), `dress-modern` (U.S. / PRC / strait nouns), and `zh` (abstract nouns in zh, its own preamble, stem, and probe). - Ladder scorecard and prediction join (plan §2.4/§2.5): `buildLadderScorecard({ plan, store })` (`packages/survey/src/ladderScorecard.ts`; CLI `ladder-scorecard --plan crisis-situated`; artifact `var/scorecards/ladder-<plan>.json`, `kind: "ladder"`) reads a plan's sittings as ladders: per item the share of code 1 with a Wilson 95% interval and an `accepted` flag (share at or above 0.5); per module the strip in `meta.rung` order with the position interval (hardest accepted, easiest rejected), `inconsistent`, and `censored` (every answered rung unanimous one way); the document's composites (force ceiling mapped to a `gameRung` by `CRISIS_SITUATED_GAME_RUNGS`, covert, mobilization, commitment, hedging, extraction, deception, settlement with t3/t4 reversed); arm deltas and informed-arm conformity on the crux against the battery; dose deltas (p5-p6, e7-e8, d6-d5); refusal rates; cost folded over every sitting of the model.
