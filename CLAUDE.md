# CLAUDE.md

> Keep this file and README.md in sync. When changing scope, tools, targets, or conventions, update both documents. CLAUDE.md is the agent-facing source of truth (how to work); README.md is the human-facing source of truth (what this is and how to use it).

## What this is

Warring States Craft: a branching multi-model war game + values instrument + judges' box, targeting the ChinaTalk "Evals for the Situation Room" contest (deadline 2026-09-01). The active plan is `var/plans/20260816_PLAN_SITUATION_ROOM_SUBMISSION.md`.

## Working rules

- Run `npm test` and `npm run typecheck` before declaring a task done; `npm run format` before committing.
- TypeScript, ESM, moduleResolution bundler, no build step for node packages (each exports `./src/index.ts`). The app builds with Vite.
- Throw `@jaypie/errors` classes, never vanilla `Error`.
- All LLM calls go through the injected `LlmClient` seam (`@modelstudies/workflows`); all persistence through the `Store` seam (`FileStore` rooted at git-ignored `var/`, one directory per model). Never import `@jaypie/llm` from browser code.
- Legacy OpenAI subjects (`packages/workflows/src/llm/legacyOpenAiClient.ts`): `gpt-4-0613`, `gpt-4`, and `gpt-3.5-turbo*` predate structured output (the Responses API rejects `json_schema` for them and ignores tools on `gpt-4-0613`), so `createLlmClient` routes an id in `LEGACY_OPENAI_MODELS` to a Chat Completions client that satisfies `format` with a forced function call, sends no temperature (the API default the paper's `create_chat` used), retries 429/5xx with backoff, and stamps usage with the snapshot the response names. The paper's `gpt-4-1106-preview` and `gpt-3.5-turbo-16k` are retired; `gpt-4-0613` (8k window; a dialog-3, 350-word game peaks near 6.9k tokens on the move-two decision call) is the surviving GPT-4 of that generation, and `gpt-3.5-turbo-16k` now aliases to `gpt-3.5-turbo-0125`. That path is not strict mode (`required` is advisory and a missing key is not an API error), so `gpt-3.5-turbo-0125` flattens a two-array schema often enough to be unfieldable; the capability table (`packages/workflows/src/llm/capabilities.ts`: `ElicitationMode` = `schema` | `text`, `TEXT_ELICITATION_MODELS`, `elicitationFor`) routes it to the text path and `gpt-4-0613` stays on the schema (80 clean arms of `study_a82834f2`).
- Text elicitation (`GameOptions.elicit`: `auto` (default, the capability table) | `schema` | `text`; `--elicit <mode>` on `game-run` and `study-run`; `Run.elicit: "text"` recorded when any seat used it, `Study.elicit` carried onto every arm, `LamparthGroup.elicit` on the report row): on a forced-choice turn a `text` model is asked twice in plain text with no `format` (`answersPrompt` withholds the menu and asks the turn's questions; `selectionPrompt` puts the menu and one instruction with the answers on the history), and `parseSelection` matches the reply against the menu. Only the selection call repeats on an invalid selection, so a retry never re-pays for the prose; `validateChoices`, `CHOICE_RETRIES`, `retries`, and `unusable` are unchanged, so the failure vocabulary and the report's exclusion are the ones already on record. The parser is deliberately narrow because single-letter ids collide with English articles (`a` is both "Military Action" and the indefinite article): the last line (or every line of a bracketed list) is read as ids only when it is id-shaped, otherwise only bracketed ids count, and with no id at all the phrases are matched against labels (exact, then a unique prefix; an ambiguous prefix is dropped, not guessed). The memo path is refused: a `text` model on a non-`choice` scenario throws `ConfigurationError` at engine construction, because `memoFormat`'s two arrays have the same exposure and nothing validates them. Two elicitations of one report is a confound, so a paired text-elicited cell of a schema model measures it.
- Dependency direction: `game`/`survey`/`judges` → `workflows`; `lake` depends on nothing but `@jaypie/errors`; `cli`/`app` → all. `app` imports types only from node packages.
- Scenario content is data (`packages/game/src/scenario/`); engine code stays scenario-agnostic. The thirteen period scenarios are chapters of one chronicle (the Seven Courts saga, `var/plans/20260823_Plan_seven_courts_saga.md`): a `ScenarioText` (`scenario/render.ts`) written once per language (`en`, `zh`) against gazetteer keys (`{qin}`, `{river}`, `{Clan}` capitalizes in en) and rendered by `buildChapter(text, { naming, language, pivot })` into a plain `Scenario`. The world module (`packages/game/src/world/`) holds the gazetteer (`GAZETTEER`: every state, body, place, river, pass, with `chronicle` (real names, the default), `masked` (the invented toponyms), and `modern` (the strait and the sea) renderings in both languages; it is `CAST_NAMES` + `PLACE_NAMES` + `FEATURE_NAMES`, the last being the named country the map draws but no seat marches to — the Wei, the Fen, the Han, the Min, the Eastern Sea, the Yunmeng marshes, the pass road, the plank roads. A feature is a gazetteer key and not a `PLACE_NAMES` key on purpose: `mentionsOf` sweeps `PLACE_NAMES` to aim a stage direction, so every key it can return has to be a place the map carries, while every key in `GAZETTEER` tightens the masked-leak check the chapter specs run), the cast (`CAST`: a durable `character` block per state, undated; it is prepended to a seat's brief when `ScenarioSeat.state` names a member), the chronicle (`CHRONICLE`: per-chapter `remembers` lines per state; `memoryBefore(state, order)` builds the "What your court remembers" block from every earlier chapter), and the vocabulary sheet. Registration order in `scenarios.ts` (`TEXTS`) is chronicle order, strict chronology: 0 `strait-states` (prologue, c. 485, Wu/Yue/Qi, structure frozen as the Lamparth bridge; `taiwan-strait` is its modern-noun twin outside the chronicle), 1 `land-register`, 2 `salt-and-iron`, 3 `heavy-coin`, 4 `famine-granary`, 5 `schools-of-the-hundred`, 6 `royal-domain`, 7 `conscription-rolls`, 8 `borrowed-road`, 9 `corridor-states`, 10 `hostage-prince`, 11 `river-works`, 12 `assassins-map`; then `PLAIN`: `taiwan-strait` and the eight `lamparth-2024-*` cells (one rendering, refuse any option). `getScenario(id, options)` renders and caches; `renderingsOf(id)` is namings × languages. Seat ids are cast keys (`qin`, `zhao`, `qi`, `council`, `mohists`); seat names and chapter titles are rendered from the gazetteer. No real person is named in played text, no year is stated (`Scenario.chapter` carries `order` and `date` for readers), and the anachronism table in the plan §1.3 is enforced by `RETIRED_TERMS` in `__tests__/chapter.ts`. Every chapter's spec calls `expectChapter(text, shape)` (en/zh isomorphism, every placeholder resolved, no modern noun, no retired term, no chronicle name under `masked`, every pivot applies) and every chapter carries `STANDING_PRIORITIES` (`scenario/shared.ts`) verbatim. `Pivot`s (`{ id, note, en: {from, to}, zh: {from, to} }`) name one pivotal phrase that occurs exactly once and substitute it before rendering; `--pivot <id>` stamps `Run.pivot` and is the treatment for "a pivotal phrase read two ways". Engine strings (`strings.ts`, `EngineStrings`, `stringsFor(scenario)`) are a table keyed by language: the `en` table is the original wording byte for byte (the Lamparth specs depend on it), and a `zh` run is judged and narrated in zh by the same table. Translation fidelity is a documented limitation: the two bodies are written, not translated, and `expectChapter` checks shape, not meaning. `Scenario.simulates` (required, `Headline: detail`) names the modern situation for readers, is rendered on the chapter pages and `/craft/play`, and never reaches a model prompt (`materials.spec.ts` checks it for every rendering, and sweeps every period rendering for `MODERN_NOUNS`; `taiwan-strait` and the Lamparth cells are exempt by id). CLI: `--language en|zh`, `--naming chronicle|masked|modern`, `--pivot <id>` on `game-run` and `study-run`; the run and the study record them.
- Lamparth replication (`packages/game/src/scenario/lamparth2024.ts`): the Lamparth et al. 2024 U.S.-China game transcribed verbatim from the MIT repo's `wargame/*.txt` (Appendix A); `buildLamparth(treatment)` builds one of eight cells (`accuracy` × `training` × `posture`; ids `lamparth-2024-<acc70|acc95>-<basic|significant>-<revisionist|statusquo>`, `LAMPARTH_2024` is the repo default acc95/basic/revisionist). It uses three scenario-agnostic engine features: `Scenario.elicitation: "choice"` (seats answer `turn.questions` and select ids from `turn.choices`; `choiceFormat(turn)` constrains the schema enum; the memo carries `answers` and `choices`, `decision` = selected labels, `options` = the menu), `ScenarioSeat.scripted` (the seat plays `turn.script[seat]`, roster records `SCRIPTED_MODEL`, no LLM call, no debrief; the matrix fills it itself and refuses a model on it), and `Scenario.record: "scripted"` (the public record between turns is the injects and scripted moves, no narrator text). Run-level treatments: `GameOptions.dialog` (N rounds of simulated team dialog before each model decision, carried as chat `history` into the decision call; the brief keeps `dialog[]`), `GameOptions.dialogWords` (a target stated in every dialog prompt, `(about N words for this round of dialogue)`; the paper's chunks were about 350 and its measures move with length, so a length-matched run passes 350; the original enforced nothing and the seam has no portable output cap, so this is an instruction, and the report carries the achieved mean per move as `dialogWords`), and `GameOptions.priorities: false` (withholds the priorities block); the run records `dialog`, `dialogWords`, and `priorities`. CLI: `--dialog <n>`, `--dialog-words <n>`, `--no-priorities`. The cells declare `seatPrompt: "bare"`: the seat's system prompt is the brief and the priorities block only, because the engine's `framed` prompt carries `summary` (which for these cells names the paper, the treatment, and move two's outcome), objectives, the ladder, and a closing line; `lamparth2024.spec.ts` asserts none of that reaches the seat. Forced-choice selections are validated (`validateChoices` in `briefs.ts`: empty, duplicated, or whole-menu selections are invalid); `elicitBrief` retries the decision call up to `CHOICE_RETRIES` times with the invalid reply on the history and `choiceRetryPrompt`, records `retries`, and when the last attempt is still invalid records `unusable` (the memo keeps what the model returned). `selectionFor` and the Lamparth report skip unusable briefs; the report counts the dropped games as `excluded` per group rather than coding them as zeros. The cells declare `report: "lamparth"`; `choices.ts` keeps per-turn helpers (`choiceStats`) for ad hoc grouping.
- Studies and reports: a study (`packages/game/src/study.ts`, `Study` in `types.ts`, files in git-ignored `var/studies/`) is scenarios × models × replicates, each arm one root run stamped with `run.study` and `run.replicate`; `planStudy` writes the arms, `extendStudy` grows a study in place (raises `replicates` and/or adds `models`, appending only the missing (scenario, model, replicate) arms as pending after the existing ones; played arms and their runs are untouched; refuses a lower count or a no-op; a default title follows the new shape), `runStudy` plays every arm that is not complete (an arm whose run finished with a failed model brief is an error and is replayed as a fresh run; an active run is resumed), `buildStudyReport` runs the study's reporting definition. Reporting definitions live in `packages/game/src/reports/` (`REPORTS`: `basic` = escalation per turn/peak/final across replicates; `lamparth` = the paper's statistics: action frequency, total causal effect per treatment factor, aggressiveness, actions selected, Table 2 consistency, and subject-minus-reference differences, every interval a seeded percentile bootstrap); `Scenario.report` names a scenario's definition (default `basic`), a study inherits it and refuses mixed scenarios without an explicit `--report`. Adding a definition: implement `ReportDefinition`, register in `reports/index.ts`, extend `ReportId`, mirror the report shape in the app types. The Lamparth report imports `packages/game/src/reference/lamparth-2024.json` (`LAMPARTH_REFERENCE`, a package asset rather than a store model; the MIT repo's human, GPT-4, and GPT-3.5 dialog-3 games as choice flags only; the repo's GPT files reproduce the paper's Table 2 as the joint probabilities p(agg2 ∧ agg1) / p(agg2 ∧ des1), which the report carries as `table2` beside the literal `conditional`). CLI: `study-run --scenarios "lamparth-2024-*" --models SOL,LUNA --replicates 10 --dialog 3` (`--plan-only`, `--resume <id>`, `--concurrency`; `--resume <id> --replicates 10` and `--resume <id> --models X,Y` extend the study before playing), `study-list`, `study-report <id>` (writes `var/reports/<id>.json`). App: `/craft/studies/:id` and `/awry/studies/:id` (the report rendered, then the arm grid with replay links; the page computes nothing).
- Fork modes: `GameOptions.matrix` (seat → candidate models) forks at turn 1 into one child per combination (`branch.lane: "matrix"`, root keeps `run.matrix`, no turns) and children never fork again; without a matrix the root plays to the scenario's decision point and forks n·2 (independent + consensus). `matrixCombinations` is the single source of the product.
- Human play: `GameOptions.human` (a `HumanPlayer`: `decide`, optional `judge` and `narrate`); any seat assigned `HUMAN_MODEL` (in `seats` or in the matrix) routes to the human every turn; `HUMAN_MODEL` on the panel routes a `JudgePrompt` to `judge` and as the `narrator` routes a `NarratePrompt` to `narrate` (the engine refuses either without the handler). Masking helpers live in `mask.ts`. Decision-point fork with `human` set adds a blind and an informed focal memo beside the roster. - Stage (plan `var/plans/20260823_Plan_stage_animated_overworld.md`, status §10): every replay on `/craft/play/:id` plays on a Phaser 4 overworld above the turn cards. The script is data: `StageScript` (`packages/game/src/stage/types.ts`, store model `stagings`, `var/stagings/<runId>[.random<seed>].json`) is beats keyed by id (`t<n>.inject`, `t<n>.brief.<seat>`, `t<n>.verdict`, `t<n>.narrative`, `debrief`), each a list of directions from the closed vocabulary (`vocabulary.ts`: `StageDirectionKind`, `DIRECTIONS` (places `at` | `route`, archetype, effect), `StageArchetype`, `StageEffect`, `Marker`, `Terrain`, `Water`), `seats` (state, home place, model), and `places` used; `validateStageScript` refuses an unknown place, a route kind without `from`/`to`, or an `at` on a route kind. Three coders: `fallback` (`fallback.ts`, escalation band → `CONSEQUENCES` kind, no model call; `weave.ts` steps a route consequence down a band when the escalator is already at the focus), `random` (`random.ts`, seeded, every seat picks a strategy at random so the weave is exercised; stored beside the default as `<runId>.random<seed>`), and `coder` (`coder.ts`, Sonnet by default, one call per turn through the seam with `format`, invalid replies retried with the validator's message; about $0.17 per six-turn game). CLI: `game-stage <runId> [--fallback | --random --seed <n> | --model <id>] [--force]`, `study-stage <studyId> [--fallback] [--model] [--force] [--concurrency]` (every complete arm), `stage-map --check` (every gazetteer key and home has a place on the map). Homes: `homes.ts` (`han` = `yiyang`, `zhou` = `luoyang`). Art sets (`packages/app/src/stage/sets.ts`, browser-safe and imported by the node build scripts): a set is a tile size, the art layers it stacks, and its own Tiled map, and `STAGE_SETS` holds two — `period-16` (fallback, vendor, period at 16 px, `overworld.tmj`) and `period-32` (those three plus `period32` at 32 px, `overworld32.tmj`, the same country one shading grade higher). `DEFAULT_STAGE_SET` is `period-32` and is the only place the default lives; `BASE_TILE` (16) is the size every scene constant is written at. `?set=<id>` picks a set on `/craft/tiles`, `/craft/map`, and `/craft/play/:id`, and `stageSetOf` resolves an unknown value to the default rather than failing. Map: `packages/app/art/map/geography.json` (fills, places, and `decor` placements on a 144 × 96 grid drawn against the historical geography, c. 250 BCE) is rendered by `npm run stage:map` to one `.tmj` per set (Tiled JSON, blob autotile indexes per ground, water tilesets with stacked frames, a `decor` object layer of embellishments (`DECOR` in `catalog.ts`: pine, bamboo, beacon, tumulus, stele, boat, horses, grove, rocks), and a `places` object layer with `type` = marker and `state`); `placesOfTiledMap` / `checkPlaces` in `tiled.ts` read only the `places` layer. A fill may also carry a `feature` (a gazetteer key), which is how the map knows the river it draws at 96,20 is the He and the one below it is the Wei. Ground and feature are rasterized in one pass (`rasterMapOf` → `RasterMap`; `rasterize` is the grid alone), so a later fill takes the cells it overpaints and a stretch is named only where it still shows, and `featureFileOf` writes the result to `public/stage/features.json` (`FeatureFile`: feature id → cell indexes) once for every set, because the grid is the same at every tile size. The sidecar is what keeps the browser scene off the node build module. The build reports each set's ground coverage (`coverageOf`: `missing`, `mismatched`, `short`), because a sheet drawn at another set's tile bound into this set's tileset renders as garbage rather than as nothing. Art layers (`packages/app/src/stage/assets.ts`, `loadStageManifest({ set })`, `STAGE_SOURCES` in order; a set names the layers it stacks and the manifest carries `set` and `tile`, and every asset its own `tile`, so the scene scales a lower layer's art by `scaleOf` = `unit * BASE_TILE / asset.tile`): `fallback` (procedural, `npm run stage:fallback`, `art/fallback/`, committed), `vendor` (the purchased packs, `npm run stage:vendor` over `art/vendor/packs.json` and `var/assets/vendor/`; an a2 / a1 sheet's `layout` (`A2Layout` in `autotile.ts`, declared per pack or per sheet) names its block's top row: `single-corners`, the VectoRaith sheets, is the single tile then the inner-corner tile, with the fill only inside the box, and `corners-fill`, the RPG Maker convention and the default, is the inner corners then the plain fill; `expandA2Block` copies the one whole tile the layout provides (the single or the fill) and composes the rest, and `fillTileOf` (the key-out base) follows it; the output `public/stage/vendor/` is git-ignored, and nothing from the packs is committed or uploaded to any generator; the packs' license forbids AI use), `period` and `period32` (generated on PixelLab for this project; a `PeriodSpec` carries its own identity — the `source` it writes, the `tile` its ground sheets are drawn at, the raw `root`, and the built `out` — so a second resolution is a second spec file rather than a second script: `art/period/items.json` is the 16 px spec and prompt record (`npm run stage:period` → `public/stage/period/`) and `art/period/items32.json` the 32 px one (`npm run stage:period32` → `public/stage/period32/`), raw downloads in git-ignored `var/assets/pixellab/`, both layers committed; a `tileset` item is a PixelLab 16-tile corner-Wang sheet, every biome chained to one shared grass base tile, and `tileset.ts` expands it to the 47-tile blob sheet by dual-grid quadrant sampling (`wangBlobSheet`: each output quadrant is the quadrant of the Wang cell centred on that tile corner, so the transition lands inside the region tile and the surround meets the ground layer's `wangFillSheet` grass), with `desaturate` (`greyBlue`) pinning the generator's violet-drifting stone to grey). The bespoke biomes are the terrain vocabulary (`TERRAINS` in `catalog.ts`: grass, tallgrass, scrub, loess, steppe, road, cobble, forest, bamboo, hills, mountain, qinling, taihang, shu, marsh, field; `RANGES` is the mountain family, `mountain` being the generic style every lesser range wears while the three named ranges carry their own generation), and `MARKER_VARIANTS` maps a marker to alternate assets (town has three) picked per place by a hash of its key. Four `items.json` options finish a generated sheet, because the generator picks its own palette and paints its transition against the one lower terrain it was chained to: `key` drops what must not travel with the biome (`lower` keys the lower palette out so the map's own layer shows through the surround instead of a collar of grass; `upper` keeps only the upper terrain's colours, which also drops the warm collar the generator paints across a transition — right for a biome whose pure tile is rich enough to carry its own outline, wrong for one of two or three colours, which upper-keying strips to a flat cut), `adjust` (`ColourAdjustment`: `hue` in degrees, `saturation`, `value`) brings a sheet into the map's range without spending another generation, `variants` stacks rearrangements of a `fill` sheet with `variantTone` giving each block its own tone, and `frames` stacks the water animation. `blocksOf` in `map/map.ts` is the one rule for how many blob blocks a ground's sheet carries (a frame apiece for water, a rearrangement apiece for grass, one otherwise) and every art layer builds to it, because the layers shadow one another by id and a layer with fewer blocks than the map addresses renders blank. A block is not a frame: `blobTileset` takes `blocks` (how tall the sheet is) and `frames` (how many of those blocks are a Tiled animation) separately, and only water passes more than one frame, because Phaser plays a declared animation and a grass sheet declared as frames makes every cell that lands on the first block cycle through the rest while its neighbours sit still. The map builder gives each fully surrounded tile one of two orientations (`orientationOf`, Tiled's flip flags added, never OR-ed) and each ground cell one of the stacked variants (`variantOf`): the horizontal mirror is the only one, because top-down art is lit from the top of the tile and mirroring it across the horizontal axis moves the light to the bottom, which turns a field of any shaded ground into a checkerboard of alternating light (a hill drawn as a lit crown over a shadowed lower side is where it shows worst). A generated Wang fill is flat by construction, so a wide field's variety comes from rearranging its few pixels rather than from a busier tile. Transitions (`pairIdOf`, `againstOf`, `groundMask` in `map/map.ts`): keying answers a ground that meets grass, but where two non-grass grounds meet neither was drawn against the other and the layer beneath is not grass, so the set carries a sheet per adjacency, `terrain.mountain@forest` being the range drawn over the wood. Each is generated chained at both ends (`lower_base_tile_id` and `upper_base_tile_id`), which is what lets it be laid in place of the plain sheet with no seam: `var/scratch/verify-pairs.mts` checks that every pair reproduces both neighbours' base tiles pixel-exactly. A pair is generated at `transition_size` 0.25 (0 where two flat grounds meet, since a Wang transition tile is itself an edge and neither ground has the relief to spend on one), never 0.5: `wangBlobSheet` samples the quadrant of the Wang cell centred on each tile corner, so a band deep enough to run past that corner leaves no pure lower ground anywhere in the composed sheet, and the pair tile — opaque, since a chained sheet is never keyed — then covers its neighbour square to the tile edge, which is a hard axis-aligned cut where a drawn boundary should be. `var/scratch/lower-share.mts` reports the share of each built pair that is its lower neighbour's own colours: 17–33% at 0.25 or 0, and 0–11% at 0.5. How many tiles come back is what `transition_size` really decides, and pro mode moves the threshold: standard returns the 16-tile Wang sheet at 0, 0.25, and 0.5 and the 25-tile `tileset15_t1` cliff sheet at 1.0, while pro returns the cliff sheet from 0.5 up. A cliff sheet's pure-lower corner is a transition tile rather than the ground it was chained to, so a range generated pro at 0.5 cannot reproduce the field it stands in and has to be keyed out, which cuts its drawn scree into floating specks; every pro range is generated at 0.25 for that reason, and it is the tile count in the reply, not the setting, that says which sheet arrived. Chaining fixes the base tile and nothing else: a sheet can reproduce the tile it was given and still draw the rest of its range in its own palette, so the build recolours rather than corrects. `matchPalette` (`tileset.ts`) maps an image from one palette onto another by luminance rank weighted by area (rank, because two renderings of the same material carry the same few shades in the same order and rank keeps the shading a nearest match would flatten; weighted, because they do not carry the same *number* of shades, and spreading nine evenly over six puts the body of one on the highlight of the other — so a `Swatch` is a colour and the pixels of the plain tile wearing it, `cornerSwatches` counts them, and each shade lands where the same share of the target's area lies). The plain tile decides the mapping but is not what the sheet wears: a generator draws the boundary in shades the plain tile never carries, and every one of those otherwise snaps to whichever entry it sits nearest, so a wide lit shoulder a shade off the ground's highlight becomes the highlight outright and the map reads a pale ribbon tracing every boundary. `matchPalette` therefore also takes `area`, the histogram of the region being recoloured (`splitFinish` classifies each pixel before recolouring so it can count both halves), and places a colour `from` does not carry by its own share of that region instead. How much of the region it covers decides which placement to trust (`BODY_SHARE`, 5%): a shade covering a body's worth of the region is that ground as this sheet draws it and goes where its own area puts it, which is the case `upperTarget` exists to close (a pair whose turf is a shade off the plain sheet's beside it — `terrain.hills@forest` drew 42% of its half in a colour the plain tile does not carry, and forcing it darker left the pair a visibly different green); a rarer shade is a detail — a rim, a fleck, a dithered edge — where the area of a handful of pixels says nothing, so it follows its nearest neighbour and may only ever be darkened, because the fault that rule was written for is a band reading brighter than the ground it belongs to and a correction that could also lighten would put a new light mark on the shore. The entries `from` does carry keep their `from`-derived place, so the base tile still reproduces pixel for pixel. `var/scratch/rim-share.mts` is the check: the share of a pair drawn in its ground's lightest shade beside the share the plain sheet of that ground wears, and a pair far above its plain sheet has a lit rim (`terrain.hills@forest` was 40 points above and is 7). `paletteAgainst` (`build.ts`) reads the colours a ground actually wears on the map from its own sheet *as the build finishes it* (`finishedSheet`, cached and recursive: a plain sheet is itself drawn against grass, so reading its raw tile answers with colours the map never shows, since `splitFinish` repaints every pixel it classifies as the lower ground — that gap is what left the hills pairs a grade lighter than the hills), and `splitFinish` takes both halves' targets: `lowerTarget` puts a chained sheet's surround onto the ground it stands in (the lime rim the bamboo grove wore is what that removed), `upperTarget` puts a pair's own half onto the plain sheet of the same ground (the ice-blue patch the Taihang wore wherever `terrain.taihang@scrub` was laid is what that removed). Both are identity for a sheet that already matched, and `var/scratch/pair-palette.mts` reports any colour in a built pair that belongs to neither neighbour. Which half a pixel belongs to is nearest palette, then two rules where nearest cannot answer. A colour both plain tiles carry is nearest to both, and a tie broken by which half is tested first hands a terrain's own body to the other one: the downland's turf is 40% of its plain tile and a handful of pixels of the meadow's brightest highlight, so an equal distance sent every one of those pixels to the meadow and the whole hills region came back painted in grass's lightest shade — a flat pale shelf a tile deep wherever the region's edge ran straight, which is the white bar the map read at every hills boundary. A tie therefore goes to whichever ground wears the colour by area (`sharesOf`); only on a tie, since a strictly nearer palette is still the answer. And the two plain tiles' boxes (`lowerBox`, `upperBox`, from `wangIndex`) are each one terrain by construction, so no guess may hand their pixels to the other half: left to the guess, a fraction of a percent of a plain upper tile comes back wearing the lower ground, and that tile is what `paletteAgainst` hands every pair of the ground as its target, so a rare stray becomes a slot in the target for a whole transition band to land in — a quarter of `terrain.hills@forest` was grass's light shade, which is a cream bar along every contact. The same tie was the lime speckle the scrub left on the Qinling crags and the Taihang ridge. The hills' `adjust` was retuned with these in place, since it had only ever been finishing the crown while half the sheet was being repainted as grass. `period-32` supplies 39 (`art/period/items32.json`, `against: "<lower>"` on the item, the upper terrain's `desaturate` / `adjust` / `frames` finish inherited, and `splitFinish` classifying each pixel by nearest palette so each half wears the colours its ground wears elsewhere); `period-16` supplies none and the build reports `0 of 0`. Laying them is two passes: `againstOf` decides per cell which lower ground that tile's boundary is drawn against (the dominant non-same neighbour of lower-or-equal `DRAW_ORDER` rank, ties to the higher rank, null when the winner is grass or the set has no sheet for the pair), and `groundMask` then reads a cell that chose this ground as this ground, so the lower ground runs whole beneath the neighbour drawing the boundary and exactly one of the two tiles carries it. `pairsOf` in `build.ts` reads the set's own manifest for `@` ids (dropping any at another set's tile or short of `blocksOf`), `buildTiledMap` registers only the pairs the map actually lays, `previewMap` mirrors both (keep it in step with the builder), and `OverworldScene.preload` loads every `@` id in the manifest because Phaser binds a tileset by name. `/craft/tiles` shows them in a Transitions section (`groupOf` → `pair`, `lowerOf` naming the bed), each patch drawn on the ground it is laid over rather than on grass. `npm run stage:preview [-- --set <id> --window x,y,w,h --zoom n --out <png>]` renders a set's map to a PNG with the same tiles the scene loads, so art is judged without a browser; `npm run stage:fetch -- [--kind tileset|object|character] [--dir <sub>] <name>=<id>` downloads a generated tileset (sheet and corner metadata), a map object, or a character's walk frames into the raw tree under that subdirectory. A one-direction object lands as a single PNG; an eight-direction object and an animated character both land as `<name>/walk/<facing>-<n>.png`, the object with one frame per facing and the character with the animation's, so a still like the barge and a walk cycle are read by the same kind of `sprite` entry. - Ladder scorecard and prediction join (plan §2.4/§2.5): `buildLadderScorecard({ plan, store })` (`packages/survey/src/ladderScorecard.ts`; CLI `ladder-scorecard --plan crisis-situated`; artifact `var/scorecards/ladder-<plan>.json`, `kind: "ladder"`) reads a plan's sittings as ladders: per item the share of code 1 with a Wilson 95% interval and an `accepted` flag (share at or above 0.5); per module the strip in `meta.rung` order with the position interval (hardest accepted, easiest rejected), `inconsistent`, and `censored` (every answered rung unanimous one way); the document's composites (force ceiling mapped to a `gameRung` by `CRISIS_SITUATED_GAME_RUNGS`, covert, mobilization, commitment, hedging, extraction, deception, settlement with t3/t4 reversed); arm deltas and informed-arm conformity on the crux against the battery; dose deltas (p5-p6, e7-e8, d6-d5); refusal rates; cost folded over every sitting of the model. The default arm reads from the full-battery sitting; the crux sitting rides as a replication check, never pooled. The prediction map (document §4) is data in `packages/survey/src/bank/crisisSituatedPredictions.ts` (`CRISIS_SITUATED_PREDICTIONS`: Lamparth rows bind by option id and numeric turn; chapter rows carry authored labels until a chapter study elicits choices; `*` rows are every chapter's T5/T6; the survey spec holds item names to the bank and `packages/cli/src/__tests__/predict.spec.ts` holds Lamparth ids to the menus and chapter ids to the registry). The join lives in the CLI (`packages/cli/src/predict.ts`; `predict --study <id> [--scorecard ladder-crisis-situated] [--no-save]` writes `var/reports/prediction-<study>.json`): per model and choice turn the options whose readings hold under the model's shares, the observed modal option pooled across cells (cells must agree on the menu), hit where the modal option carries a prediction, chance 1/|menu|, the cross-model modal as the consensus baseline, and the declared `gameRung` beside the judge's peak escalation; models absent from the scorecard are reported `noSurvey`, and unjoined map rows are counted, never dropped silently.
- Usage and cost: `LlmOperateResult.usage` (`LlmUsageItem[]`, one per model call) comes back through the seam; the Jaypie client stamps `usd` on each item with `priceUsage` (`packages/workflows/src/llm/pricing.ts`, table = `LLM.COST` over `LOCAL_PRICES` for ids Jaypie lacks, today the Lamparth-era `gpt-3.5-turbo-0125`, `gpt-4-0613`, and `gpt-4o-2024-08-06`; provider rules in `billableTokens`: Anthropic `input` is already uncached and `output` includes thinking, OpenAI-style providers carry cache reads inside `input` and reasoning inside `output`, Google reports reasoning beside output).
