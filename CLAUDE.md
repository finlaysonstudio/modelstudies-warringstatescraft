# CLAUDE.md

> Keep this file and README.md in sync. When changing scope, tools, targets, or conventions, update both documents. CLAUDE.md is the agent-facing source of truth (how to work); README.md is the human-facing source of truth (what this is and how to use it).

## What this is

Warring States Bench: a branching multi-model war game + values instrument + judges' box, targeting the ChinaTalk "Evals for the Situation Room" contest (deadline 2026-09-01). The active plan is `var/plans/20260816_PLAN_SITUATION_ROOM_SUBMISSION.md`.

## Working rules

- Run `npm test` and `npm run typecheck` before declaring a task done; `npm run format` before committing.
- TypeScript, ESM, moduleResolution bundler, no build step for node packages (each exports `./src/index.ts`). The app builds with Vite.
- Throw `@jaypie/errors` classes, never vanilla `Error`.
- All LLM calls go through the injected `LlmClient` seam (`@modelstudies/workflows`); all persistence through the `Store` seam (`FileStore` rooted at git-ignored `var/`, one directory per model). Never import `@jaypie/llm` from browser code.
- Legacy OpenAI subjects (`packages/workflows/src/llm/legacyOpenAiClient.ts`): `gpt-4-0613`, `gpt-4`, and `gpt-3.5-turbo*` predate structured output (the Responses API rejects `json_schema` for them and ignores tools on `gpt-4-0613`), so `createLlmClient` routes an id in `LEGACY_OPENAI_MODELS` to a Chat Completions client that satisfies `format` with a forced function call, sends no temperature (the API default the paper's `create_chat` used), retries 429/5xx with backoff, and stamps usage with the snapshot the response names. The paper's `gpt-4-1106-preview` and `gpt-3.5-turbo-16k` are retired; `gpt-4-0613` (8k window; a dialog-3, 350-word game peaks near 6.9k tokens on the move-two decision call) is the surviving GPT-4 of that generation, and `gpt-3.5-turbo-16k` now aliases to `gpt-3.5-turbo-0125`.
- Dependency direction: `game`/`survey`/`judges` → `workflows`; `lake` depends on nothing but `@jaypie/errors`; `cli`/`app` → all. `app` imports types only from node packages.
- Scenario content is data (`packages/game/src/scenario/`); engine code stays scenario-agnostic. The thirteen period scenarios are chapters of one chronicle (the Seven Courts saga, `var/plans/20260823_Plan_seven_courts_saga.md`): a `ScenarioText` (`scenario/render.ts`) written once per language (`en`, `zh`) against gazetteer keys (`{qin}`, `{river}`, `{Clan}` capitalizes in en) and rendered by `buildChapter(text, { naming, language, pivot })` into a plain `Scenario`. The world module (`packages/game/src/world/`) holds the gazetteer (`GAZETTEER`: every state, body, place, river, pass, with `chronicle` (real names, the default), `masked` (the invented toponyms), and `modern` (the strait only) renderings in both languages), the cast (`CAST`: a durable `character` block per state, undated; it is prepended to a seat's brief when `ScenarioSeat.state` names a member), the chronicle (`CHRONICLE`: per-chapter `remembers` lines per state; `memoryBefore(state, order)` builds the "What your court remembers" block from every earlier chapter), and the vocabulary sheet. Registration order in `scenarios.ts` (`TEXTS`) is chronicle order, strict chronology: 0 `strait-states` (prologue, c. 485, Wu/Yue/Qi, structure frozen as the Lamparth bridge; `taiwan-strait` is its modern-noun twin outside the chronicle), 1 `land-register`, 2 `salt-and-iron`, 3 `heavy-coin`, 4 `famine-granary`, 5 `schools-of-the-hundred`, 6 `royal-domain`, 7 `conscription-rolls`, 8 `borrowed-road`, 9 `corridor-states`, 10 `hostage-prince`, 11 `river-works`, 12 `assassins-map`; then `PLAIN`: `taiwan-strait` and the eight `lamparth-2024-*` cells (one rendering, refuse any option). `getScenario(id, options)` renders and caches; `renderingsOf(id)` is namings × languages. Seat ids are cast keys (`qin`, `zhao`, `qi`, `council`, `mohists`); seat names and chapter titles are rendered from the gazetteer. No real person is named in played text, no year is stated (`Scenario.chapter` carries `order` and `date` for readers), and the anachronism table in the plan §1.3 is enforced by `RETIRED_TERMS` in `__tests__/chapter.ts`. Every chapter's spec calls `expectChapter(text, shape)` (en/zh isomorphism, every placeholder resolved, no modern noun, no retired term, no chronicle name under `masked`, every pivot applies) and every chapter carries `STANDING_PRIORITIES` (`scenario/shared.ts`) verbatim. `Pivot`s (`{ id, note, en: {from, to}, zh: {from, to} }`) name one pivotal phrase that occurs exactly once and substitute it before rendering; `--pivot <id>` stamps `Run.pivot` and is the treatment for "a pivotal phrase read two ways". Engine strings (`strings.ts`, `EngineStrings`, `stringsFor(scenario)`) are a table keyed by language: the `en` table is the original wording byte for byte (the Lamparth specs depend on it), and a `zh` run is judged and narrated in zh by the same table. Translation fidelity is a documented limitation: the two bodies are written, not translated, and `expectChapter` checks shape, not meaning. `Scenario.simulates` (required, `Headline: detail`) names the modern situation for readers, is rendered on `/scenarios` and `/play`, and never reaches a model prompt (`materials.spec.ts` checks it for every rendering, and sweeps every period rendering for `MODERN_NOUNS`; `taiwan-strait` and the Lamparth cells are exempt by id). CLI: `--language en|zh`, `--naming chronicle|masked|modern`, `--pivot <id>` on `game-run` and `study-run`; the run and the study record them.
- Lamparth replication (`packages/game/src/scenario/lamparth2024.ts`): the Lamparth et al. 2024 U.S.-China game transcribed verbatim from the MIT repo's `wargame/*.txt` (Appendix A); `buildLamparth(treatment)` builds one of eight cells (`accuracy` × `training` × `posture`; ids `lamparth-2024-<acc70|acc95>-<basic|significant>-<revisionist|statusquo>`, `LAMPARTH_2024` is the repo default acc95/basic/revisionist). It uses three scenario-agnostic engine features: `Scenario.elicitation: "choice"` (seats answer `turn.questions` and select ids from `turn.choices`; `choiceFormat(turn)` constrains the schema enum; the memo carries `answers` and `choices`, `decision` = selected labels, `options` = the menu), `ScenarioSeat.scripted` (the seat plays `turn.script[seat]`, roster records `SCRIPTED_MODEL`, no LLM call, no debrief; the matrix fills it itself and refuses a model on it), and `Scenario.record: "scripted"` (the public record between turns is the injects and scripted moves, no narrator text). Run-level treatments: `GameOptions.dialog` (N rounds of simulated team dialog before each model decision, carried as chat `history` into the decision call; the brief keeps `dialog[]`), `GameOptions.dialogWords` (a target stated in every dialog prompt, `(about N words for this round of dialogue)`; the paper's chunks were about 350 and its measures move with length, so a length-matched run passes 350; the original enforced nothing and the seam has no portable output cap, so this is an instruction, and the report carries the achieved mean per move as `dialogWords`), and `GameOptions.priorities: false` (withholds the priorities block); the run records `dialog`, `dialogWords`, and `priorities`. CLI: `--dialog <n>`, `--dialog-words <n>`, `--no-priorities`. The cells declare `seatPrompt: "bare"`: the seat's system prompt is the brief and the priorities block only, because the engine's `framed` prompt carries `summary` (which for these cells names the paper, the treatment, and move two's outcome), objectives, the ladder, and a closing line; `lamparth2024.spec.ts` asserts none of that reaches the seat. Forced-choice selections are validated (`validateChoices` in `briefs.ts`: empty, duplicated, or whole-menu selections are invalid); `elicitBrief` retries the decision call up to `CHOICE_RETRIES` times with the invalid reply on the history and `choiceRetryPrompt`, records `retries`, and when the last attempt is still invalid records `unusable` (the memo keeps what the model returned). `selectionFor` and the Lamparth report skip unusable briefs; the report counts the dropped games as `excluded` per group rather than coding them as zeros. The cells declare `report: "lamparth"`; `choices.ts` keeps per-turn helpers (`choiceStats`) for ad hoc grouping.
- Studies and reports: a study (`packages/game/src/study.ts`, `Study` in `types.ts`, files in git-ignored `var/studies/`) is scenarios × models × replicates, each arm one root run stamped with `run.study` and `run.replicate`; `planStudy` writes the arms, `extendStudy` grows a study in place (raises `replicates` and/or adds `models`, appending only the missing (scenario, model, replicate) arms as pending after the existing ones; played arms and their runs are untouched; refuses a lower count or a no-op; a default title follows the new shape), `runStudy` plays every arm that is not complete (an arm whose run finished with a failed model brief is an error and is replayed as a fresh run; an active run is resumed), `buildStudyReport` runs the study's reporting definition. Reporting definitions live in `packages/game/src/reports/` (`REPORTS`: `basic` = escalation per turn/peak/final across replicates; `lamparth` = the paper's statistics: action frequency, total causal effect per treatment factor, aggressiveness, actions selected, Table 2 consistency, and subject-minus-reference differences, every interval a seeded percentile bootstrap); `Scenario.report` names a scenario's definition (default `basic`), a study inherits it and refuses mixed scenarios without an explicit `--report`. Adding a definition: implement `ReportDefinition`, register in `reports/index.ts`, extend `ReportId`, mirror the report shape in the app types. The Lamparth report imports `packages/game/src/reference/lamparth-2024.json` (`LAMPARTH_REFERENCE`, a package asset rather than a store model; the MIT repo's human, GPT-4, and GPT-3.5 dialog-3 games as choice flags only; the repo's GPT files reproduce the paper's Table 2 as the joint probabilities p(agg2 ∧ agg1) / p(agg2 ∧ des1), which the report carries as `table2` beside the literal `conditional`). CLI: `study-run --scenarios "lamparth-2024-*" --models SOL,LUNA --replicates 10 --dialog 3` (`--plan-only`, `--resume <id>`, `--concurrency`; `--resume <id> --replicates 10` and `--resume <id> --models X,Y` extend the study before playing), `study-list`, `study-report <id>` (writes `var/reports/<id>.json`). App: `/studies` and `/studies/:id` (arm grid with run links, then the report JSON rendered; the page computes nothing).
- Fork modes: `GameOptions.matrix` (seat → candidate models) forks at turn 1 into one child per combination (`branch.lane: "matrix"`, root keeps `run.matrix`, no turns) and children never fork again; without a matrix the root plays to the scenario's decision point and forks n·2 (independent + consensus). `matrixCombinations` is the single source of the product.
- Human play: `GameOptions.human` (a `HumanPlayer`: `decide`, optional `judge` and `narrate`); any seat assigned `HUMAN_MODEL` (in `seats` or in the matrix) routes to the human every turn; `HUMAN_MODEL` on the panel routes a `JudgePrompt` to `judge` and as the `narrator` routes a `NarratePrompt` to `narrate` (the engine refuses either without the handler). Masking helpers live in `mask.ts`. Within a turn, model seats decide first and human seats last; the `HumanPrompt` carries `roster`, `history` (that run's own prior turns) and `table` (the other seats' briefs this turn). Decision-point fork with `human` set adds a blind and an informed focal memo beside the roster. Human prompts are masked: every model id other than `HUMAN_MODEL` reads `MASKED_MODEL` (roster, history briefs, panel) and the `table` is shuffled; the stored run keeps the truth. The `/play` console withholds replay links from a seated human until the session completes. The browser path is `packages/app/server/play.ts` (Node-side, loaded by the Vite plugin through `ssrLoadModule`, sessions in memory, matrix only) behind `/api/play/*`, and the `/play` pages. The server module is the one place in `app` that imports node packages at runtime; browser code still imports types only.
- Matrix view (`packages/app/src/pages/MatrixView.tsx`, `/runs/:id/matrix`): every comparison dimension is an `Axis` (`seat` from the roots' unioned `matrix`, `panel` = judges × `PanelMode`, `root` = source matrix root), and filtering, color-by, split, and the branch table all iterate axes. The `panel` and `root` axes appear only when the combined roots vary in them; a new panel mode needs no view change. `?with=<ids>` combines further matrix roots of the same scenario (same-scenario check, per-root failures dropped with a note); the combine picker reads `matrix`, `panel`, and `narrator` from the `/data/runs.json` index built in `packages/app/vite.config.ts` (mirrored in `RunIndexEntry`).
- Adjudication: `adjudicateTurn` takes a `PanelConfig` (`judges`, `mode`; `PANEL_MODES` lists the combining modes, only `median` today; add a fold to `COMBINE` in `adjudicate.ts` and the union in `types.ts` together) and a `narrator`. `GameOptions.panel` is partial (judges default to the roster, mode to `median`); the run records `panel` and `narrator`. `adjudicateTurn` takes `human` and routes `HUMAN_MODEL` judges and narrator to it; the play server exposes these as `/api/play/:id/judge` and `/api/play/:id/narrate` (session `verdicts` and `narrations`). There is no gate.
- Usage and cost: `LlmOperateResult.usage` (`LlmUsageItem[]`, one per model call) comes back through the seam; the Jaypie client stamps `usd` on each item with `priceUsage` (`packages/workflows/src/llm/pricing.ts`, table = `LLM.COST` over `LOCAL_PRICES` for ids Jaypie lacks, today the Lamparth-era `gpt-3.5-turbo-0125`, `gpt-4-0613`, and `gpt-4o-2024-08-06`; provider rules in `billableTokens`: Anthropic `input` is already uncached and `output` includes thinking, OpenAI-style providers carry cache reads inside `input` and reasoning inside `output`, Google reports reasoning beside output). Dollars are stamped at call time on purpose: the price then is what the call cost; never re-rate history. The engine stores usage on the artifact each call produced: `DecisionBrief.usage` (dialog rounds then the decision call), `PanelVerdict.usage`, `TurnAdjudication.narratorUsage`, `Debrief.usage`; human and scripted artifacts carry none, and `mask.ts` strips usage from human-facing prompts (items name the provider and model). Folds live in `packages/game/src/cost.ts`: `usageOf(run)` counts only the run's own calls (a decision-point branch's inherited turns and seeded briefs belong to the parent), `usageOfRuns`/`usageOfTree` sum without double counting, `groupUsage` regroups rows by any key; rows are (role, seat, model). `ReportBase.usage` (`studyUsage` in `reports/types.ts`) carries the study's total, rows, by-model, and per-cell cost per game. The app mirrors the fold in `packages/app/src/lib/usage.ts` (keep it in step with `cost.ts`) and renders `UsageSection` on `/runs/:id` (the run and its fetched branches) and `/studies/:id` (from the report). CLI: `game-cost <runId>` (`--json`), `game-list` shows each run's own cost.
- Rosters use `MODEL` constants mirrored in `packages/survey/src/models.ts` (browser-safe mirror of `@jaypie/llm` `LLM.MODEL`; drift is CI-checked). Panels: `dev` for development speed, `production` for full runs.
- Runtime storage is `var/` (git-ignored): every store model is a directory `var/<model>/<id>.json` (`runs`, `studies`, `interview`, `probe`, `scorecards`, `reports`, `scenarios`), and the CLI and play server construct `new FileStore(<repo>/var)`; there is no `data/` directory and no committed run artifact. Curated inputs live with the code that reads them (the Lamparth reference under `packages/game/src/reference/`). The app's dev server serves `var/<model>` at `/data/<model>/<id>.json` (the URL prefix is a route, not a directory; indexes at `/data/runs.json`, `/data/studies.json`, `/data/scenarios.json`). Scenario materials (every card and prompt, rendered with no history) are exported by `npm run materials` to `var/scenarios/<id>[.<naming>][.<language>].json`, one file per rendering (`materialsId`; each carries `base`, `renderings`, `cast`, `pivots`), and rendered at `/scenarios` (the index lists the default rendering per scenario with its `renderings`; the page switches renderings and shows the chapter, cast, and pivots); `npm run app` and `npm run dev` export them first (`preapp`/`predev`), so a fresh checkout needs no manual step, and re-export after editing scenario content or prompt builders while the server is running. The run schema lives in `packages/game/src/types.ts` and is mirrored in `packages/app/src/lib/types.ts` — change both together.
- Document lake (`var/lake/`, git-ignored): the source corpus behind scenario authoring, `simulates` grounding, and the ladders. Acquisition stays in `var/lake/bin/` (hand-run `.mjs` ingesters, HTTP-cached under `.cache/`, one registry entry per source in `sources-<collection>.mjs`; `build-index.mjs` and `search.mjs` are shims onto the CLI). Retrieval is `@modelstudies/lake`: a `Lake` seam (`FileLake` over the tree, `MemoryLake` for tests) plus `searchLake`, `getDocument`, `listDocuments`, and `buildLakeIndex`. The wall is a type signature, not an instruction: `use` (`prompt` may reach a seat, `reader` informs `simulates` and never a prompt, `internal` is method reference) is a required option on search, get, and list, `ANY_USE` is a value a caller has to type, and `getDocument` refuses a document on the other side of the caller's use. `wall.spec.ts` asserts it, as `materials.spec.ts` asserts `simulates` never reaches a prompt. Every hit and window carries the manifest's `citation`, and `rights`/`redistribute` govern what may travel with the submission bundle (only `public-domain`, `open-license`, `government`). Ranking is BM25 over whole documents scaled by term coverage; lexical, so an embedding sidecar belongs beside it, not instead of it. `lake-index` is the only writer of `var/lake/index.json` (`--verify` recomputes sha1 and word counts). CLI: `lake-search "<query>" --use prompt`, `lake-get <id> --use prompt --from <line> --lines <n>`, `lake-list`, `lake-index`. When the chat assistant lands, its `search_lake` / `get_document` tools wrap these functions rather than reimplementing them. Retrieval practice (which `use` a task takes, the Chinese-first period corpus, window sizing against line geometry, the rights check before quoting, and the trip conditions for raising the embedding sidecar with the operator rather than rephrasing past a lexical miss) is the `lake` skill in `.claude/skills/lake/`; keep it in step with the package.
- Upstream provenance: composition engine, survey core, judges, label pipeline, and the visual system are lifted from `finlaysonstudio-cloudagent` (see plan §Extraction Map). Do not propose upstream fixes from this repo; note candidate contributions in the plan instead.
